新增 [13 个可重复的本地例子](../tokenguard_v04/EXAMPLES.md)，全部通过。pytest 修复前/后实际运行 504 项测试，检查 3 个失败变为 0、测试未改和整个失败段落保留；8 个压缩案例的 Artifact 字节一致，16 次有界 grep/show 恢复成功且审计匹配；5 个安全透传案例逐字符相等。它们是本地工具与手动 Hook 子进程验证，不是新的付费/真实 Claude 集成实验。

这些例子复现 Windows CLI CRLF 被二次翻译、实际输出字符数与审计不一致的问题，并发现继承 ASCII 输出编码时 Unicode 恢复失败。CLI 已固定 UTF-8 并关闭换行翻译。新增 4 项子进程回归（含 8 个换行 subtests）验证 Unicode、LF/CRLF/CR/无末尾换行和混合换行；修复前可重复失败、修复后全部通过。磁盘原始 Artifact 无需修改。

本机已用安装的 Claude Code 2.1.181 运行无模型预检：从 npm 入口旁定位原生程序，验证版本/help 参数、独立 Hook 响应和 Artifact，以及初始 504 项测试中 3 个失败可复现。新增覆盖原生入口解析、失败不消耗会话、未找到程序、旧 JS 安装、环境禁用 Hook、过期计划和错误测试数。预检本身不调用模型，不能代替真实任务验证。

随后仅按明确授权启动 1 轮、2 个新 Claude CLI 会话，请求模型 deepseek-flash，使用 no_hook 基线，传入 --max-turns 8、每会话超时 180 秒，保持现有权限。两组均只修改 arithmetic.py，分别通过独立的原始 504 项测试，初始 3 个失败可复现。Agent 墙钟时间为基线 19.560 秒、优化组 13.302 秒，此单次差异不能证明性能收益。

优化组的 Hook 实际调用 3 次，收到 stdout 为 201、810、891 字符，全部低于 3000 阈值，诊断均为 below_threshold。实际压缩 0 次、恢复 0 次；这是压缩条件未满足，未观察到 Hook 调用失败。当前证据不能解释工具上游为何输出较短，也不能证明本轮真实宿主消费了压缩替换，因为没有发出替换。

CLI 提供了 input/cache/output 聚合计数，原始响应仅保留本地。它们与供应商原生请求级 Usage、完整覆盖验证和实际账单分开；本轮不计算或宣称 TokenGuard 节省率。CLI 的 num_turns 报告为 11/8，不能作为独立 API 请求计数；--max-turns 已按计划传入，API 轮数未独立观测。官方仓库有[类似计数口径报告](https://github.com/anthropics/claude-code-action/issues/1795)，该报告的复现版本与本机不同，不能当作本机限额执行已获独立认证。

本地任务 Fixture 原始 504 项测试中 3 项失败，修复后通过全部 504 项。优化组压缩了 pytest 输出并保留失败详情；基线组同样安装 Hook，但关闭压缩。Mock 不模拟 API Token/费用，没有绑定 usage 的报告明确保留 unavailable。三轮任务实验包含 6 个独立 trial，运行方法见 [任务实验文档](../tokenguard_v04/TASK_EXPERIMENTS.md)。

新增两种基线各三轮的 Mock 对照，共 **12/12** 任务通过。默认 disabled_hook 基线共启动 6 个 Hook 子进程，无压缩；no_hook 基线启动 0 个，输出字符完整保留。两个独立优化组各发生 6 次压缩，修复后均通过 504 项测试。进程时间只作为本地描述性数据，不能证明真实性能或费用收益。不同基线禁止交叉配对或混入同一 Usage cohort；通用旧导出基线信息未知时标为 unspecified。

先前 CI 发现 Windows Python 3.12 的路径 stat 与句柄 fstat 在 ctime 含义上可能不同。索引现统一持久化/读取句柄指纹，跨 API 比较仅使用文件身份、大小和 mtime，同一 API 仍检查 ctime，并保留修改与文件替换保护。参考 [CPython #157671](https://github.com/python/cpython/issues/157671)。
