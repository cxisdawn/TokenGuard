## 先复现，再修复

| 问题 | 复现依据 | 修复及验收 |
| --- | --- | --- |
| 警告消息被当作通过记录删除 | 实际 pytest 输出 `UserWarning: critical::contract PASSED` | 只聚合可信 Python 节点的进度行；警告、捕获输出、插件报告和汇总之后完整保留 |
| 参数 ID 内的 `::` 被当成节点分隔符 | 参数化节点 `test_case[value::1]` | 解析文件与 Python 节点，再剥离参数；不确定名称保留原文 |
| 恢复提示改变汇总行的 CR 结尾 | 严格检查完整物理行，先复现两项失败 | 复用原有 CR/LF/CRLF 边界；无换行末尾才添加分隔符 |
| 实时 stdout 伪装成通过记录 | 实际运行 `-s`、`--capture=no`、`tee-sys`，及 ini 隐式配置 | 显式实时捕获模式或独立状态、被打断节点触发 `ambiguous_pytest_live_output`，整段透传；测试证明仅校验 PASSED 数量不足 |
| 长行尾部无法恢复 | 超过 12000 字符的单行，关键词位于旧返回窗口之外 | 行号和行内字符双游标；grep 显示完整匹配窗口，show 可逐段重建原始字节 |
| grep 命中上限被误报为完整结果 | 三行均匹配，limit=1 返回无截断提示 | 最多额外读一个字符探测尾部；未扫描完时提供双游标 |
| 索引校验后原文变化，返回错误行 | 实际在索引返回后、读取过程中分别改写隔离 Artifact | 对实际读取句柄和路径执行前后状态校验；变化时失败，不记录成功恢复 |
| 无效结果被算作成功 | 评分无效、越界修改、损坏结果和缓存成功标记 | 有效失败与未知结果分开；保留计划分母；重新核对测试凭证和当前源码 |
| 比较证据中的未知状态被当作通过 | 收据缺少超时字段、基线缓存 0 次但当前流有压缩、读取期间配置改变 | 严格类型检查、当前基线污染检查；配置及全部快照文件纳入读取一致性校验 |

pytest 的输出仍是文本，没有可信的行来源标记。完全模仿测试进度且没有可见异常的插件输出，无法仅凭文本认证；`off` 模式仍是关闭 pytest 压缩的入口。未证明所有任意输出都可无损压缩，未调整默认 `compact` 模式或替用户重装 Hook。

## 可重复的真实本地输出检查

```powershell
# 在仓库根目录；使用已有 Python 环境也可以。
$Python = (Resolve-Path .\.venv\Scripts\python.exe).Path
& $Python -X utf8 -m pytest -q
& $Python -X utf8 .\tokenguard_v04\verify_hook.py
& $Python -X utf8 .\tokenguard_v04\benchmark\pytest_contracts.py
```

脚本创建独立临时项目，实际运行 12 类 pytest Fixture。每类输出经过三种模式和 LF/CRLF/CR 三种换行形式，共 108 项 Hook/恢复检查。换行变体由同一实际输出转换，均明确标记。检查范围：

- 完整警告及失败报告段、重要状态、最终汇总和原工具响应的其他字段。
- 应压缩的场景确实压缩；关闭和实时输出歧义场景逐字透传。
- Artifact UTF-8 字节一致；按行恢复和关键词恢复都与原始行比较。
- 实际 CLI 输出字符数与审计返回量一致；压缩和恢复次数与实际进程结果一致。
- 验证器及运行源码执行前后的 SHA256 不变；记录 Python/pytest 版本。

每次在新的 `reports/contracts/pytest-contracts-.../` 保存 JSON、CSV、Markdown、合成源码及前后日志。Fixture 超时、异常退出、无效 UTF-8、检查失败均使报告失败；失败退出码不可忽略。验证器自身有负对照：故意改变汇总行、破坏报告首行边界、删除未预设关键词的失败详情、减少重复警告，必须被拒绝。无效编码原始字节保存在隔离报告目录，供本地排查。

可将同一个验证器指向旧版本源码，确认它能检出原有缺陷，旧源码不会被改写：

```powershell
& $Python -X utf8 .\tokenguard_v04\benchmark\pytest_contracts.py `
  --implementation 'C:\reference\TokenGuard\tokenguard_v04'
```

这里故意分别调用 show 和 grep 来覆盖两个接口。因此报告中的恢复次数用于验证契约，不能用来比较 Agent 恢复效率。所有调用均标为 `manual`；真实 Claude 集成、模型能力、实际 API Token 和账单没有在本轮重新测量。

## 长行恢复规则

```powershell
$Id = 'ARTIFACT_SHA256'
$Cid = 'COMPRESSION_ID'
& $Python .\tokenguard_v04\tg.py grep $Id '关键词' --context 1 --max-chars 2000 --compression-id $Cid

# 将响应中的 next_start_line 和 next_start_char 同时填入。
& $Python .\tokenguard_v04\tg.py show $Id --start 1 --start-char 15000 --count 1 --max-chars 2000 --compression-id $Cid
```

`--start` 从 1 计行；`--start-char` 从 0 计该行内的 Unicode 字符，包含原始换行字符，不是 UTF-8 字节偏移。续读必须使用两个游标。grep 的 `[char N]` 表示返回窗口在原始行中的起点；过大的上下文被省略时有明确提示，并计入返回字符预算。

单次返回上限仍为 12000 字符，内容扫描上限仍为 8 Mi 字符加一个探测字符。预算放不下完整匹配或续取信息时，CLI 明确失败，退出码 2、正文为空。关闭索引或索引不可写时，如果扫描预算内到不了请求位置，也会明确失败；需要启用或修复索引，不会无限扫描或重复返回旧游标。失败请求不记录为一次成功恢复。

新的稀疏索引支持长行内的 Unicode 字符定位；旧索引可自动重建，原 Artifact 不修改。首次索引构建完整读取原文，其字节成本仍单列。回归覆盖无末尾换行、混合换行、CRLF 与 UTF-8 块边界、大小写折叠、超扫描预算长行和固定种子的分页重建。达到 grep 匹配条数上限时也会提示尚未扫描的尾部，完整提示计入返回预算；不为确认后面是否还有匹配而扫描整份原文。

对实际恢复句柄进行打开前后与读取完成后的状态校验。发生并发改写时明确失败，不返回可能来自旧索引的错行。该保护检测文件身份、大小和时间状态的变化，不是对能伪造本地文件与指纹的恶意同用户进程的认证机制。

## 评测结论的边界

有效独立评分确认未修复记为 `false`；缺失、损坏或无效证据记为 `null`/证据不足。它们都保留在计划样本中。代码修复、Agent 正常完成、比较协议充分性分别呈现，缺少测试凭证不会把已有有效失败改成成功，也不会把已确认的正常结束改写为模型失败。

汇总会重新读取测试凭证、对应 stdout/stderr、全部初始快照、最终可编辑源码及固定配置、任务与官方实例；读取前后校验这些输入及凭证目录成员，并在观察区间内复核固定输入，避免依赖缓存的成功字段。收据必须明确提供布尔型超时/截断标志和整数退出码。当前 Bash 与审计证实的基线压缩不能被缓存的零计数掩盖。历史报告原文件保留，可另行生成新汇总。缺失 Token/费用/恢复测量不填零，真实提供商用量与账单仍为 `unavailable`。

本轮只读复核三个既有实验、共十个会话，没有重新启动 Agent 或评分器。代码修复计数保持原样：20 轮原生组基线 0/3、优化 1/3；40 轮原生组基线 1/1、优化 0/1；40 轮受控组基线 1/1、优化 0/1。前两组不补认证为完整协议成功；受控组仍有一对证据充分的比较，结果为基线成功、优化失败。不同条件分别报告，不合并成总体成功率。
