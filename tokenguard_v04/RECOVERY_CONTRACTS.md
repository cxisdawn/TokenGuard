# 原文恢复独立评测

这是本地软件行为评测，不启动模型、不读取用户历史 Artifact，不测量编码能力、整个任务 Token 或实际账单。所有输入均为固定样例或固定种子生成的合成日志；每次创建独立报告及数据目录，保留之前的报告。

## 运行

在仓库根目录执行：

```powershell
$Python = 'D:\tokenguard-benchmark\.venv\Scripts\python.exe'
Push-Location .\tokenguard_v04
& $Python -X utf8 .\benchmark\recovery_contracts.py
Pop-Location
```

脚本打印报告目录和通过数量，成功退出 0，任何未完成、缺失或失败检查退出 1。目录含 `report.json`、`report.csv`、`report.md`、独立 worker 的 stdout/stderr，以及生成的隔离 Artifact/审计。默认写入被 Git 忽略的 `reports/recovery-contracts`。可以通过 `--output` 指定父目录；不会覆盖旧报告或删除 Artifact。

`--implementation C:\work\TokenGuard\tokenguard_v04` 可检查另一份受信任的本地源码。该选项会执行指定实现，包括 `tg.py`；只应用于自己确认可信的源码，不是运行不可信代码的沙箱。父进程不导入目标包，独立 worker 清除继承的 TokenGuard 数据目录等设置，并将所有恢复数据指向本次报告目录。测试不改变现有 Hook、Claude 权限、全局配置或模型设置。

## 样例与验证口径

共 67 项检查：

| 分组 | 数量 | 验证内容 |
| --- | --- | --- |
| 固定边界 | 6 | 上下文命中分页、默认返回预算、游标位数、扫描 EOF、跨扫描关键词及实际默认扫描上限 |
| show 重建 | 13 | Unicode、CR/LF/CRLF、行内控制字符、长行及原文内伪装的续读标记 |
| grep 跨扫描分页 | 48 | 固定种子的长行、Unicode casefold、上下文和命中上限组合 |

每项检查验证返回字符预算、审计计数、游标严格推进、有限页数内完成以及 Artifact 字节不变。`show` 将各页正文逐字符拼回原文；`grep` 用独立物理行 oracle 确定命中行集合，并验证返回片段与原文对应位置一致，不把“仍出现了关键词”当作内容完整的充分证据。

续读标记按审计游标核对并只移除精确的末尾标记，避免把原文中相同格式的文字误当分页元数据。`(no matches)` 本身也可能是原文，show oracle 不盲目删除这一字符串。

报告逐行标记执行方式和参数：

- `driver=cli`：2 项实际 `tg.py` 子进程，保持生产默认边界，分别测试默认 12000 字符返回预算和 8,388,608 字符扫描上限。
- `driver=api`：65 项独立 worker 内的存储 API 检查，不冒充实际 CLI。
- `profile=production_bounds`：4 项保持实际参数。
- `profile=scan256_index64`：63 项明确将扫描上限缩至 256 字符、索引块/步距缩至 64 字节，以稳定穿过多个边界。这是压力参数，不能作为生产读取量、延迟或节省率的测量。

grep 评估的是命中行最终可达，不保证返回整条长行、每个重复出现位置或全部上下文。有限样例通过也不是任意输入的形式证明。页数、扫描字符和耗时只描述这些强制分页样例；报告不将其外推为任务效率。

## 证据与失败

每份报告绑定目标运行源码、验证脚本及完整样例清单 Hash，检查运行前后的源码文件集合与字节。新增模块也会使源码不一致；这不是签名，不能防御同一用户在检查之间修改并恢复文件的行为。

缺失、重复、身份不符、无效计量或自相矛盾的 worker 记录均不能通过。超时、异常和未返回的样例保留完整计划分母，并输出失败行；不把尚未执行当作零错误。JSON 报告拒绝 NaN，模型用量和账单保持 `unavailable`。

新验证器的单元测试覆盖 Unicode 字符偏移，并包含丢失命中、同长篡改、伪标记、worker 缺失/损坏、超时、布尔伪装整数、超大数字及运行中新建模块等负对照：

```powershell
Push-Location .\tokenguard_v04
& $Python -X utf8 -m pytest tests/test_recovery_contracts.py -q
Pop-Location
```

开发时首轮完整评测 65/67 通过，两个失败是上下文分页尾部留下孤立行号 `2`，并非关键词丢失。另以 6 项 CR/LF/CRLF 小预算反例确认：现将放不下完整前缀与至少一个正文字符的记录留到下一页，避免部分标签；续读位置与原文保留。原首轮报告保留，后续成功不能覆盖它。

2026-10-28 最终当前实现 67/67；同一验证器对完整导出的历史 `d048c89` 实现为 61/67，验证器及样例清单 Hash 相同。6 项失败分别为两个上下文漏检、一项游标预算错误，以及三个含无法识别记录的分页样例（其中一个也漏检）；并非六项都丢失关键词。完整回归 1061 passed、1 skipped、406 subtests passed；手动 Hook 及三轮 Mock 30/30 通过。88 个 Python 源码/测试文件在本轮完整验证前后 Hash 一致。本轮不新增模型调用、真实宿主消费或编码质量测量。
