# 受控日志真实 A/B：一次负面结果

2026-10-23 对公开 SWE-bench Verified 任务 `pylint-dev__pylint-6528` 完成了一对真实 Claude CLI 会话。**基线完成修复，优化组未完成修复，并引入回归。现有结果不支持“压缩不影响编码能力”。** 这是单任务、单配对的观察，尚不能确定差异由压缩造成。

## 执行范围

- 请求模型 `deepseek-flash`；Claude CLI `2.1.181`；执行源码归档对应 `fb08cd9`。
- 同一初始源码、基础任务指令、固定容器镜像、测试助手；基线先运行，优化组后运行；两个全新会话，无自动重试。
- 双方传入 `--max-turns 40`，每会话超时 600 秒。CLI 返回的 `num_turns` 分别为 42、41；这个参数及 CLI 计数不等于独立计量的工具往返或 API 请求上限。
- 协议 `controlled_initial_log`：控制器真实运行初始测试，基线接收原始 stdout，优化组接收同一 stdout 的压缩版及选择性恢复入口。实际序列化 Prompt 因这项干预而不同。
- 初始 stdout 为 16,661 字符，压缩交付为 1,769 字符，包含元数据；字符减少约 89.4%。初始测试为 168 passed、1 xfailed、1 warning；XFAIL、警告、最终汇总仍保留。
- 原文、摘要交付文件、预检及执行代码均保留 Hash；启动前复核。原文 Artifact 字节校验通过。双方未修改受保护测试或配置。

使用官方测试脚本和判分指标，但源码选择与 Agent 编排为本项目实现，并固定了已记录的兼容依赖 `tomlkit==0.10.1`。这不是完整官方排行榜评测。环境、原始与参考修复预检见 [SWE_BENCH_QUALITY.md](SWE_BENCH_QUALITY.md)，交付证据口径见 [QUALITY_PROTOCOL.md](QUALITY_PROTOCOL.md)。

双方独立判分均有效，均完整观察到预期测试项。上游测试脚本在测试完成后的清理阶段，仍出现已记录的新测试文件不在 base commit 的 pathspec 错误；报告保留其退出码与错误，只按既有严格条件识别该清理问题。它不能掩盖优化组的 13 项实际测试失败。

受控压缩交付的比较证据通过；优化组未完成要求的全套最终可见测试，这项不遵循另行保留，没有被当作测试通过。两组后续均未发生原生 Hook 压缩，因此这一对不能用来证明原生工具响应替换的质量效果。优化组记录了 27 次 Hook 诊断：20 次 `below_threshold`、2 次 `incomplete_pytest`、5 次 `insufficient_saving`。这是正常安全透传的具体原因，不能描述成 Hook 未触发。

## 本地复盘能确认什么

基线修改了递归发现文件时的 ignore 处理。优化组最终补丁只有两条调试 `print`，没有功能修复。只在内存中移除这两条新增行后，文件字节与初始源码完全一致；没有修改或重新提交 Agent 的候选补丁，也没有用人工修复替换评测结果。

优化组新增的 9 项原有测试失败，其报错直接包含调试打印对正常 stdout 的污染。它使用了少量定向测试，最终在诊断阶段触及轮数上限。控制器的初始日志没有 FAILED 或 ERROR，不能把此次失败解释为压缩器删掉了初始失败详情。

隐藏 PASSED 测试名称是否影响了后续导航、模型随机性和执行策略各自的作用尚未确定。一个有压缩暴露的负面配对足以否定“已经验证无损”的说法，但不足以证明普遍退化或因果归属；也不能与此前不同协议、不同预算的八个会话合并成一个成功率。
